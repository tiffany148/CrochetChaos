Technical editing examines whether a pattern is internally correct and sufficiently specified. Pattern testing investigates whether people can follow it and what the resulting objects do. Copyediting and proofreading check different layers. Keep those records separate so one successful check does not imply that every kind of review has occurred.

For this book, computer calculations are recorded as arithmetic checks. They do not count as physical samples, independent technical editing, fitting, or regulatory testing. An honest status label is part of technical accuracy.

## Freeze a reviewable version

Give the pattern a version identifier and retain the exact file sent for review. Include its chart, schematic, materials, terminology, notes, special stitches, and finishing. A reviewer cannot assess a complete construction from a partial set of pages or a photograph alone.

Separate open design questions from instructions. If a neckline dimension is still undecided, resolve it in sampling or identify it as an open prototype issue. Do not quietly ask testers to design the missing section while calling the instructions complete.

## Arithmetic audit

For every row or round, check input destinations, output units, repeat count, beginning-chain treatment, joining treatment, and shaping change. Confirm that repeated instructions end at the stated row number. Check units before converting dimensions into counts.

An audit table can have columns for row, input, repeat, output, and comment. For a decrease from 30 to 24, six repeats of [sc in next 3 sts, sc2tog] consume 30 and produce 24. That verifies the count relationship. It does not verify the resulting curve or appearance.

When a script checks an example, state what was encoded. A handful of assertions cannot prove every sentence in a long book. If instructions change, update the checks and rerun them rather than retaining an obsolete pass result.

## Chart and schematic audit

Translate the chart to words and the words back to a chart. Include edge units, row direction, shared boundaries, and special-stitch placement. For a color grid, count cells by color. For filet, verify the stated block convention and shared-edge math. For a symbol chart, trace attachments rather than merely counting symbols.

Compare every schematic dimension with the count and gauge that support it. Identify whether it includes borders, overlaps, seams, or folded cuffs. A flat-width label that should be circumference can create a twofold size error even when all stitches are counted correctly.

## Physical sample record

Record who made the sample, which version they used, yarn and lot, hook, actual gauge, finished treatment, actual dimensions, and consumption if measured. Photograph important stages with clear orientation. Do not assign observations from one version to another after revisions.

For garments, record fit and movement in the intended wearing configuration. For dog clothing, include the individual’s measurements, willing fitting observations, opening clearance, and equipment compatibility. For stuffed forms, inspect filling retention, attachment, and intended-use limitations. A test in one material and size does not establish every substitute or grade.

## Tester instructions

Ask testers to follow the written version and record where they needed clarification, changed a method, or could not continue. Distinguish a pattern error from a tester’s intentional customization. Collect the original wording and actual result rather than only a general statement that the pattern was easy.

Do not require a tester to continue through a suspected unsafe or destructive step. Pause that step, preserve their observations, and revise the design or test plan. A failed test is useful evidence when it is recorded accurately.

| Review area | Useful tester observation | Unhelpful substitute |
|---|---|---|
| Repeat clarity | Exact row and phrase that caused uncertainty | “Something was confusing” |
| Count | Expected count, actual count, and interpretation | “I added a stitch to fix it” without a note |
| Gauge | Measured span, stitch pattern, and treatment | Hook size alone |
| Fit | Actual dimensions and movement observations | Size label alone |
| Materials | Measured use or stated estimation method | Unexplained ball count |
| Revision | Exact changed step and version | Recollection after the file was overwritten |

## Resolve feedback systematically

Log each issue with a unique identifier, location, evidence, proposed correction, and resolution. If several testers misread the same instruction, improve the instruction even if the designer can explain its intended meaning afterward.

After changing a count or construction step, audit dependent rows, charts, dimensions, materials, and captions. A corrected increase can alter every later count. Update the whole affected chain rather than fixing only the line where the error was noticed.

Retest the changed region and any affected downstream construction. Routine proofreading of the revised sentence does not establish that the new shape works physically.

## Publication proof

Assemble the book and inspect the actual rendered pages. Check broken tables, clipped text, missing glyphs, awkward page references, legibility, and consistency between the Word and PDF. Confirm that final files contain the accepted version of each pattern.

After pagination is stable, build and verify the index and contents. Recheck current printer specifications for trim, margins, binding, page-count limits, embedded fonts, and required PDF format. A visually clean reading proof is not automatically a compliant print interior.

## Errata and version history

When an error is found after distribution, identify the affected version and exact correction. Explain whether stitch counts or construction change and where readers can safely resume. Keep prior versions available in the project record so a report can be matched to the file the reader actually used.

Do not silently change a pattern and assume earlier readers now have the correction. A clear errata note is part of supporting a published design, not evidence that the designer should have been infallible.

## Review exercise

Take the original basket in Chapter 70. Audit every count, then map its handles, then list all claims that require a physical sample. The handles’ positions can be checked mathematically. Their comfort, shape, and strength cannot. Create a test sheet that preserves that distinction.

## What a tech editor checks

| Area | What is checked |
|---|---|
| Math | Every stitch count, repeat and size |
| Consistency | Abbreviations, terms (US or UK), formatting |
| Completeness | Materials, gauge, sizes, finishing, notes |
| Charts and schematics | Match the written instructions |
| Clarity | Every instruction can be followed without guessing |

> [!DANG] Dang, I Wish I'd Known That! — Testers and tech editors do different jobs
